# 第一章：全景 — OmO 是什么

## 一句话总结

OmO（Oh My OpenCode）是一个 TypeScript 插件，挂载到 OpenCode（开源 AI 编程 CLI）上，把单模型单代理的编程助手变成多模型多代理协作团队。

## OmO 和 OpenCode 的关系

```
┌──────────────────────────────────┐
│  OpenCode（宿主）                 │
│  开源 CLI，类似 Claude Code       │
│  自身能力：                       │
│    - 会话管理                     │
│    - 调一个 AI 模型               │
│    - 基础工具 (read/edit/bash)    │
│                                  │
│  ┌────────────────────────────┐  │
│  │  @opencode-ai/plugin 接口  │  │  ← 标准插件协议
│  └─────────────┬──────────────┘  │
│                │                 │
│  ┌─────────────▼──────────────┐  │
│  │  oh-my-opencode（OmO）     │  │  ← 本项目
│  │  增强：                     │  │
│  │  - 10 个代理                │  │
│  │  - 8 种模型路由             │  │
│  │  - 26 个工具                │  │
│  │  - 47+ hook                │  │
│  │  - 后台并行                 │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘
```

OmO 不是独立应用。OpenCode 在运行时加载 OmO，OmO 通过拦截点注入自己的全部功能。

## 入口文件

整个项目只有一个导出：

```typescript
// src/index.ts:20
const OhMyOpenCodePlugin: Plugin = async (ctx) => {
  // ctx 包含：client（SDK 客户端）、directory（工作目录）
  // ...初始化...
  return pluginInterface  // 返回 8 个拦截点
}
export default OhMyOpenCodePlugin
```

## 5 步初始化

OpenCode 启动时调用这个 Plugin 函数，OmO 按顺序执行 5 步：

```
loadPluginConfig()      ← 第 1 步：读取并合并配置
      ↓
createManagers()        ← 第 2 步：创建 4 个管理器
      ↓
createTools()           ← 第 3 步：注册 26 个工具 + 加载 Skill
      ↓
createHooks()           ← 第 4 步：组装 48 个 Hook
      ↓
createPluginInterface() ← 第 5 步：暴露 8 个拦截点给 OpenCode
```

### 第 1 步：配置加载

```
~/.config/opencode/oh-my-opencode.jsonc  （用户级配置）
         +
.opencode/oh-my-opencode.jsonc           （项目级配置）
         ↓
    mergeConfigs() 深度合并
         ↓
    Zod safeParse 校验
         ↓
    最终配置对象
```

- 用户级配置是全局默认值
- 项目级配置覆盖用户级
- 无效配置段跳过不崩溃（部分加载）

### 第 2 步：4 个管理器

| 管理器 | 职责 |
|--------|------|
| TmuxSessionManager | 管理 tmux 窗格的创建/布局/清理 |
| BackgroundManager | 管理后台代理任务的生命周期 |
| SkillMcpManager | 管理 Skill 对应的 MCP 服务器 |
| ConfigHandler | 向 OpenCode 注册代理配置 |

### 第 3 步：工具注册

- 加载所有 Skill（内置 + 用户 + 项目，6 个来源）
- 解析 Category 配置（8 种任务类别 → 8 种模型）
- 注册 26 个自定义工具（task、call_omo_agent、grep、glob、lsp_* 等）

### 第 4 步：Hook 组装

```
createHooks()
  ├── createCoreHooks()           39 个
  │     ├── createSessionHooks()     23 个
  │     ├── createToolGuardHooks()   12 个
  │     └── createTransformHooks()    4 个
  ├── createContinuationHooks()    7 个
  └── createSkillHooks()           2 个
```

### 第 5 步：暴露拦截点

```typescript
// src/plugin-interface.ts
return {
  tool:                          // 注册自定义工具
  config:                        // 注册代理配置
  "chat.message":                // 每条消息发送前拦截
  "chat.params":                 // 修改 API 请求参数
  "chat.headers":                // 注入请求头
  "experimental.chat.messages.transform":  // 变换消息列表
  "experimental.chat.system.transform":    // 变换系统提示
  event:                         // 响应所有事件
  "tool.execute.before":         // 工具执行前
  "tool.execute.after":          // 工具执行后
  "tool.definition":             // 工具定义变换
}
```

## 技术栈

| 技术 | 用在哪 | 为什么选它 |
|------|--------|----------|
| Bun | 运行时+构建+测试+包管理 | 比 Node 快，原生 TS 支持 |
| TypeScript strict | 全项目 | 类型安全 |
| Zod v4 | 配置校验 | 运行时类型检查，自动生成 schema |
| @opencode-ai/plugin | 插件接口 | OpenCode 官方 SDK |
| @opencode-ai/sdk | 会话/代理操作 | 创建会话、发消息、管理代理 |
| @ast-grep/napi | AST 代码搜索 | 比正则精准，理解语法结构 |
| vscode-jsonrpc | LSP 通信 | IDE 级代码分析 |
| @modelcontextprotocol/sdk | MCP 工具 | 标准化的外部工具协议 |
| commander | CLI | 命令行解析 |
| JSONC | 配置格式 | JSON + 注释，对人友好 |

## 核心设计理念

1. **多模型编排** — 不锁定单一 AI 提供商，按任务匹配最合适的模型
2. **代理分层** — 编排层（调度）、专家层（执行）、工具层（原子操作）
3. **成本感知** — FREE 工具 > CHEAP 代理 > EXPENSIVE 代理
4. **权限隔离** — 每个代理只拥有完成职责所需的最小权限
5. **容错设计** — 模型 fallback、错误恢复、会话恢复、循环续跑
